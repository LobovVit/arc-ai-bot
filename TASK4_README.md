# Task 4 — Реализация RAG-бота с техниками промптинга (Go + Telegram)

## Цель
Собрать работающего RAG-бота, который:
- ищет релевантные фрагменты в векторной БД (Qdrant);
- формирует ответ с опорой на найденные данные;
- использует техники улучшения качества ответа: **Few-shot** и **Chain-of-Thought** (в формате краткого объяснения);
- умеет отвечать **«Я не знаю»**, если ответ не найден или релевантность низкая.

## Архитектура
- **Embeddings**: локально через сервис `embeddings_service` (Sentence-Transformers)
- **Vector DB**: Qdrant
- **LLM**: YandexGPT по умолчанию (через OpenAI-совместимый endpoint), fallback на Stub, если креды не заданы
- **Интерфейс**: Telegram-бот

## Настройка
1) Создайте `.env`:
```bash
cp .env.example .env
```
2) Заполните `TELEGRAM_BOT_TOKEN` и  `YANDEX_API_KEY`, `YANDEX_FOLDER_ID`.

## Запуск
1) Поднять сервисы:
```bash
docker compose up -d qdrant embeddings
```
2) Построить индекс (если не делали в Task 3):
```bash
docker compose run --rm ingest
```
3) Запустить Telegram-бота:
```bash
docker compose up -d bot
```
Логи:
```bash
docker compose logs -f bot
```

## RAG-пайплайн
1) Пользователь задаёт вопрос в Telegram.
2) Вопрос преобразуется в embedding (локально).
3) Выполняется поиск top-k чанков в Qdrant.
4) Строится промпт:
   - System: правила ответа строго по context + структура ответа
   - Few-shot: 2 примера (файл `prompts/fewshot_ru.md`)
   - Context: топ чанков из Qdrant
5) LLM генерирует ответ.
6) Бот добавляет секцию **«Источники»**.

## Few-shot
Примеры лежат в `prompts/fewshot_ru.md` и задают стиль ответа в рамках той же вселенной (Asterion Saga).

## Chain-of-Thought
Вместо раскрытия внутренней цепочки рассуждений модель просим давать **краткое объяснение** в 2–4 пункта на основе контекста.

## Правило «Я не знаю»
Бот отвечает «Я не знаю», если:
- ничего не найдено, или
- релевантность слишком низкая: `topScore < MIN_SCORE` (по умолчанию 0.45)
